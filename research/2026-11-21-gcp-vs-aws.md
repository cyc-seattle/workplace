# Running the platform on AWS instead of GCP

The maintainer asked whether to move the platform from Google Cloud to AWS, now that the newsletter brings an AWS
account for Amazon SES ([cyc-seattle/platform#180](https://github.com/cyc-seattle/platform/issues/180)). This compares
what the same platform would cost and take to run on each, as of November 2026. It follows the cost review in
[cyc-seattle/platform#171](https://github.com/cyc-seattle/platform/issues/171).

## Recommendation

Stay on GCP. A like-for-like AWS setup costs about the same as GCP did before #171's cuts, and more than GCP costs
after them. Moving would take about 4 to 8 weeks of work, at least one Directus license activation, and a planned
outage, and would end up locked in to AWS as much as we are to Google now. Keep AWS for SES and nothing else.

If the goal is a much smaller bill, the lever isn't another big cloud. It's fewer always-on parts: dev goes away once
the tests run in CI (#171, decision 3), and later, perhaps, everything runs on one rented server. Both are below.

## What we run

Monthly costs are list prices times what we use, from #171's measurements. AWS prices are us-west-2 (Oregon) list
prices, not checked against a quote.

| Part | On GCP today | AWS equivalent |
| --- | --- | --- |
| Containers, prod: Directus, Authentik (server and worker), FreeScout, Listmonk, sail-team (2), two sync Jobs | GKE Autopilot | ECS on Fargate, or EKS |
| Containers, dev: the same plus fakes, Mailpit, Greenmail, smoke | Autopilot, on Spot | Fargate Spot (ECS only) |
| Postgres: prod (all apps' databases), dev | Cloud SQL, `db-g1-small` and `db-f1-micro` | RDS, `db.t4g.small` and `db.t4g.micro` |
| HTTPS in, certificates | Gateway (global load balancer), Certificate Manager | Application Load Balancer, ACM |
| Fixed outbound IP for the Workspace SMTP relay | Cloud NAT | NAT Gateway, or a NAT instance |
| Secrets | Secret Manager (29) | Secrets Manager, or SSM Parameter Store |
| DNS, images, files | Cloud DNS, Artifact Registry, Cloud Storage | Route 53, ECR, S3 |
| Logs, uptime checks, alerts | Cloud Logging and Monitoring | CloudWatch |
| The public website | Firebase Hosting | S3 and CloudFront, or keep Firebase |
| Deploys from Actions without keys | Workload Identity Federation | IAM OIDC provider for GitHub |
| Backups away from the main region | `csc-backups` project | A second region or account |

| Prod containers | 63 | 57, or 41 with item 2 below | 57, or 41 | 81 |
| Dev containers | 19 | 13 | 0 | 32 |
| Cluster control plane | 0 (free credit) | 0 | 0 | 0 on ECS, 73 on EKS |
| Paid metrics | 39 | 0 | 0 | 0 (Container Insights off) |
| Postgres, prod | 28 | 28 | 28 | 26 |
| Postgres, dev | 9.50 | 9.50 | 0 | 14 |
| Load balancer | 18 | 18 | 18 | 22 |
| Outbound IP | 10 | 8 | 7 | 4 (NAT instance) to 37 (NAT Gateway) |
| Secrets | 1.50 | 1.50 | 1.50 | 0 (Parameter Store) to 12 (Secrets Manager) |
| Logs | 0 (under 50 GB free) | 0 | 0 | 11 (26 GB at $0.50, 5 GB free) |
| DNS, images, files, keys | 4 | 3 | 3 | 4 |
| **Total, $/month** | **about 192** | **about 138 to 122** | **about 114 to 98** | **about 194**, or 267 on EKS |

Why AWS comes out no cheaper:

- **Fargate's smallest task is 0.25 vCPU and 0.5 GB.** Autopilot goes down to 50m, and five of our pods are smaller
  than Fargate's floor. Per vCPU-hour the two are within 10% of each other.
- **EKS charges $73 a month for the control plane.** GKE's free credit covers our one cluster. ECS has no fee, but
  then the Kubernetes code (`src/workload.ts`, every stack's Deployments) gets rewritten as ECS task definitions.
- **AWS charges for things GCP gives us free**: logs past 5 GB, and Secrets Manager at $0.40 a secret. Parameter Store
  avoids the second.
- **A NAT Gateway is $33 a month before data.** A NAT instance (the open-source `fck-nat` on a `t4g.nano`) is about $4,
  but it's a server we patch.
- Where AWS is cheaper, it's by a dollar or two (RDS prod, DNS).

New AWS accounts get up to $200 of credits for 6 months. That's one-time, so it doesn't change the monthly bill.

## What moving would take

All of the platform's infrastructure code is written against GCP. Roughly, by stack:

| Work | Size |
| --- | --- |
| `infra`: network, NAT, cluster or ECS, load balancer, certificates, DNS, Cloud SQL, uptime checks, log alerts, Firebase site | Rewrite |
| `bootstrap`: deploy identities, state buckets and KMS keys, backups project, website deploy | Rewrite |
| `src/` helpers (`Workload`, `WebService`, `ScheduledJob`, `StateBucket`, `ServiceAccount`), a published contract sail-team codes against | Rewrite on ECS; mostly kept on EKS |
| `backend`, `authentik`, `inbox`, `listmonk`, `smoke`: Kubernetes parts | Small changes on EKS; rewrite on ECS |
| Secrets: 29 values to copy, plus each app's code that reads them | Small |
| sail-team's deploy, and the org's reusable `deploy.yml` with its Workload Identity login | Rewrite the login and the image push |
| Data: each Postgres database dumped and restored, files buckets copied | A planned outage of a few hours |
| DNS: `cycsail.team` and the other zones move, or keep Cloud DNS pointing at AWS | Small |
| Tests and docs: every unit test that mocks GCP resources, `docs/` for deploys, backups, restore drills | Large |

About 4 to 8 weeks of agent and maintainer time, with the maintainer applying `bootstrap` by hand and approving each
step. It can't overlap the Dec 23 website launch.

What can't leave Google either way:

- **gsuite-sync and the Groups sync** call Google Workspace's APIs as a GCP service account with domain-wide
  delegation. A GCP project stays for that. It costs nothing on its own.
- **Google sign-in in Authentik** uses an OAuth client that lives in a GCP project.
- **The SMTP relay** is Workspace's. It would allow AWS's NAT IP instead; that's a setting.

Risks particular to the move:

- **Directus's license.** An activation is bound to the database and `PUBLIC_URL`, and we have 5. A restored database
  on RDS may count as new, so prod and dev each risk spending one (cyc-seattle/isthmia#172).
- **Minors' data.** The CRM's records, including medical notes, would move to a new processor. That's AWS, under the
  same kind of terms as Google, but it needs a look before the move, not after.
- **Two clouds during the move**, with secrets, DNS and deploys split between them.

## Lock-in

Neither choice is free of it. The portable parts are the same on both: container images, plain Postgres, files in a
bucket, and DNS records. What ties us to a cloud is the managed glue around them:

- On GCP: Autopilot's billing, the Gateway and Certificate Manager, Cloud SQL's IAM logins, Workload Identity, Secret
  Manager, Cloud Monitoring alerts, Firebase Hosting.
- On AWS with ECS, more: the task definitions replace Kubernetes, so the next move would be a rewrite again. EKS keeps
  the Kubernetes parts portable, at $73 a month.

Today's design already keeps the lock-in thin: apps are containers, data is Postgres, and the apps (sail-team, the
website) code against `@cyc-seattle/platform`, not against Google. A move to AWS would trade one set of glue for
another, at the cost of the work above.

## If the bill is still too high after #171

In order of saving for the effort:

1. **Dev goes away** once the tests run in CI. Already decided (#171, decision 3). About −$23, to roughly $100 a month.
2. **Prod Directus and Authentik at their measured size**, if a minute of downtime when Autopilot moves them is
   acceptable. About −$16.
3. **One rented server** running the containers and Postgres (k3s or Docker Compose), with nightly backups to object
   storage. A US-region VM with 4 vCPU and 8 GB costs about $25 to $50 a month at Hetzner, DigitalOcean, or as a GCP or
   AWS VM. All-in, about $40 to $60 a month. It gives up managed point-in-time recovery, automatic node upgrades, and
   the load balancer's managed certificates, and puts patching and restores on the maintainer. Directus moves
   database, so it risks an activation. It's the only option that roughly halves the bill again, and it's a bigger
   change than #171 decided against on 2026-11-09 (Cloud SQL stays). Revisit after the launch, with a real bill in
   hand.
